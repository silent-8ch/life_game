## How this works

**Ownership is by path, not by task.** The two agents collide on files, not on features, so
the split below is designed to keep them out of each other's way. Two files are still the real
contention risk — `level-viewport.tsx` (1017 lines) and `inspector.tsx` (1156) — and most of
the work left touches one of them.

| Path | Owner |
| --- | --- |
| `app/**`, `database/**` | **1** |
| `resources/js/types/**` | **1** — this is the contract between them |
| `resources/js/components/editor/**`, `resources/js/lib/editor/**` | **1** |
| `resources/js/lib/engine/**` | **A** |
| `resources/js/components/game/**` | **A** |

## How a cross-lane fix lands

Settled by two instances tonight, one in each direction, and worth writing down because it
cost nobody anything either time.

**Whoever finds it writes it. Whoever owns the lane reviews and lands it.** The art session
found the coincident-flats z-fight and the black pane in agent A's files, wrote both with
tests, and handed them over as a patch rather than pushing. A reviewed, ran them, landed them,
and credited the reasoning and the tests in the commit. Nothing was slower for it.

The alternative was tried first and was worse: agent A wrote 5,259 lines into agent 1's
seeders without declaring it (ISSUE-50). The work was right and it still stands — but it was
caught unmerged rather than in the history, and only because planning happened to read the
branch. **The rule is worth nothing if it only applies to the cheap cases**, which is why it
was enforced against A for a good commit and is being enforced the same way against everyone.

## Working agreement

- Rebase on `main` before opening work; land small and often.
- Do not edit a path you do not own without saying so here first. If a task genuinely needs
  to, split it and hand the other half over.
- A feature is done when its plan's verification section passes, not when the code compiles.
  `composer ci:check` green — that runs eslint, prettier, phpstan and the Pest suite.
- Raise anything unexpected as an ISSUE here rather than fixing it silently in an unrelated
  branch — a surprise fix in someone else's file is how the merge goes wrong.
- **After every rebase onto `main`: `php artisan migrate` *and* `npm install`.** Both fail in
  the other agent's lane and both present as something else — the migration as a 500 on the
  page, the install as `vitest: command not found` failing the gate. ISSUE-33 and ISSUE-40.
- **When checking that a test has teeth, confirm the break actually landed** before trusting
  the failure. A patch that silently misses leaves a green suite that reads as proof. ISSUE-43.
- **Close your Chrome tabs when a verification run finishes.** They are page loads in the
  user's real browser, nobody can close another session's tabs, and the WebGL context pool is
  about sixteen deep. ISSUE-54.
- **Do not chain a push behind a piped check.** `cmd | tail && git push` pushes whatever
  happens, because a pipeline's status is the last stage's. ISSUE-40.
- **`npm install` in a worktree installs for everybody** — `node_modules` is a symlink to the
  main checkout — **and rewrites `package-lock.json`'s `name`** to the worktree's directory.
  Put the name back to `life_game2` by hand before committing. ISSUE-23.
- **(superseded, see above) Run `php artisan migrate` after every rebase onto `main`.** Migrations land in agent 1's
  lane and break agent A's worktree, and the symptom is a 500 on the page rather than anything
  that names the database. See ISSUE-33 — an hour was nearly spent on the wrong explanation.
- **If your own change makes a line in a rules file false, you own that line**, whatever lane
  the file is in. Fix it in the same commit and say so after. A rules file asserting something
  untrue is worse than one pointing somewhere stale. Anything beyond that — a new rule, a
  rewrite, a rule you merely disagree with — comes to planning first.
- Planning reads `main` and rewrites this file there. Do not edit `docs/tasks.md` yourself —
  tell planning what you need recorded, or say it in your merge commit, and it gets folded in.
